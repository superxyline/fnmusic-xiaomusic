## 4. 架构（v2 单容器）

```
小爱音箱 ──语音──> 小米云 <──轮询── xiaomusic（pip 内嵌，mount 到 /xm/）
                                    │
                          bridge（FastAPI app.py，58091）
                          ├─ 三步向导（static/wizard.html）
                          ├─ /playlist.json（歌单，xiaomusic 拉取）
                          ├─ /play?guid=xx（音频流代理 → 飞牛音乐）
                          └─ sync_loop（5min）：拉收藏 → 乱序歌单 → 推 xiaomusic
飞牛音乐（fnOS :5666）<── fnmusic_client.py（authx 签名/Cookie）
fnmusic-ext（proxy 接管 :5666）——搜索增强（本地曲库+在线源）、在线取流
```

### 关键机制（都在 `bridge-v2/app.py`，靠 monkey-patch 实例方法生效）

| patch / 机制 | 作用 |
| --- | --- |
| `patch_playlist_behavior` → 包装 `XM.play_music_list` | 口令点歌单时清 `playlist2music`+`cur_music`，强制重新洗牌从头播 |
| `patch_play_search` → 包装 `XM.play` | 点歌：先宽松匹配收藏（命中用「歌手 - 标题」精确播）；未命中走 `_resolve_song` |
| `_resolve_song` | 收藏 → 本地曲库（guid 非 `online:` 前缀，收藏以便点播）→ 在线歌（guid `online:*`）走 `_download_online_track` |
| `_download_online_track` | `open_stream()` 拉 proxy 流 + ffmpeg 转 mp3 存 `/data/music/` + refreshlist。**不进收藏** |
| `_spawn_auto_playlist_guard` | 点播后轮询 `dev.is_playing` + `command_handler.last_cmd` 快照；自然播完且无新指令 → `play_music_list("本地收藏")` |
| `push_playlist` | 每次同步全量推送 `keywords_playlist`（14+ 变体）+ `user_key_word_dict={"播放":"play"}` + `keywords_playlocal="播放下载歌曲"`（**自愈式**，防配置被覆盖） |

### 口令机制（xiaomusic 侧）

- 匹配顺序 = `Config.init()` 的追加顺序：**playlocal → play → online → singer → stop → playlist → user（最后）**
- 「播放」放 `user_key_word_dict`（顺序最末）→「播放晴天」落 play（arg1=歌名），不抢「播放本地歌曲」等 playlist 词
- `keywords_playlocal` 默认含「播放本地歌曲/播放本地音乐」会抢词 → 已改为「播放下载歌曲」

## 5. 常用操作

### 打包 FPK（本地骨架 → NAS 合成）

```bash
cd E:/codex/fnmusic-xiaomusic
# ① 同步 bridge-v2 → fpk-v2-src/app/docker/fnmusic-app/（app.py/static/requirements/Dockerfile）
# ② 本地打骨架（fnpack Windows 版会丢 cmd 权限位和 UTF-8 manifest）

# ③ 上传骨架（凭据走环境变量）
set NAS_HOST=192.168.31.26 & set NAS_USER=SuperxylineNas & set NAS_PASS=***
python scripts/nas_ssh_put.py xiaomusic-fnmusic-base.fpk /home/Aadmin/xiaomusic-fnmusic-v2-base.fpk
# ④ NAS 合成（脚本会放静态 ffmpeg 进构建上下文 + docker build/save + 注入）

# ⑤ 下载：python scripts/nas_ssh_get.py /home/Aadmin/xiaomusic-fnmusic-<ver>.fpk . --md5 <md5>
```

## 6. 踩坑全集（新会话必读，都是实测付出的代价）

1. **xiaomusic 启动会用 setting.json 全覆盖构造参数**：conf_path/hostname/public_port 等会被旧值污染 →
   app.py 的 `create_xiaomusic` 里 `update_config` 强制修正 + `save_cur_config`
2. **改 setting.json 必须 `docker stop -t 1` + sleep 15 等完全停止再改**——默认 stop 的优雅退出会触发
   xiaomusic 把内存旧配置写回，覆盖你的修改
3. **中文经 nas_ssh.py 命令行传输会损坏**（UTF-8 变逗号）——中文一律走脚本文件（put 后执行）或 base64；
   脚本要 `sed -i "s/\r$//"` 去 CRLF
4. **GitHub push 三重坑**：①全局 `url.https://ghproxy.net/.insteadOf` 会把 push 重写到只读代理（502），
   必须临时移除（`git config --unset` 对含斜杠 key 无效，**用 python 按行编辑 ~/.gitconfig**）；
   ②本机全局代理 127.0.0.1:7350 会 502；③成功组合 = 清 ghproxy + `git -c http.proxy=http://192.168.31.26:7890 push`，
   push 完恢复 ghproxy 配置
5. **fnpack Windows 版**丢 cmd 权限位（repack_fpk.py 修 0o755）+ 丢 manifest 中文（repack_fpk.py 用
   `fpk-v2-src/manifest` 原文替换）
6. **静态 ffmpeg 被 docker pull 覆盖**：后台 pull mwader/static-ffmpeg 完成后覆盖 ffbin/ffmpeg（135MB 7.1 版）；
   Dockerfile 已加 `.dockerignore`（排除 ffmpeg-static）+ `COPY --chmod=0755`（免 chmod 层）
7. **发布前隐私审查**（AGENTS.md 强制）：已删 edge-debug-profile（浏览器登录数据）、含 NAS 密码的调试脚本；
   nas_ssh_put/get.py 凭据改环境变量。**每次 push 前照此自查**
8. **驱动真实设备的验证**：只查日志/health；必须实测播放先征询用户（用户投诉过音箱"自己播放"）
9. Gitee Release 附件单文件限 100MB（184MB FPK 需拆分卷）；GitHub 单 push 文件限 100MB（FPK 只能进 Release）
10. 飞牛搜索参数是 `q=` 不是 `keyword`（官方后端 100002）；在线 guid 以 `online:` 开头可区分本地/在线
